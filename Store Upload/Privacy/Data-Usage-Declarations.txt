Tabcove contains no networking code at all. There is no fetch, XMLHttpRequest,
WebSocket, EventSource, or navigator.sendBeacon anywhere in the source, and
tools/validate.py fails the build if one appears. With no transmission path,
nothing can be collected.

3. IF A REVIEWER QUERIES "WEB HISTORY"
--------------------------------------

This is the one category a reviewer might push back on, because the extension
does store URLs. The distinction that matters:

  Tabcove stores the URLs of tabs the user EXPLICITLY CHOOSES TO SAVE, in
  chrome.storage.local on the user's own device. That is user-initiated local
  storage, not collection of browsing history.

  The extension never reads chrome.history — it does not request the history
  permission and could not read it if it wanted to. It never observes
  navigation: it has no content scripts, no webNavigation permission, and no
  host permissions. And it never transmits anything, because it contains no
  networking code.

  Nothing is "collected" in the policy's sense, because no data ever leaves the
  device.


4. IF A REVIEWER QUERIES "USER ACTIVITY"
----------------------------------------

  Tabcove records no clicks, no mouse position, no scroll position, and no
  keystrokes. It stores only what the user asked it to save (tab titles and
  URLs) plus their own settings and a timestamp of their last export. There is
  no analytics library, no telemetry, and no "share anonymous usage data"
  toggle — deliberately, and it is written into docs/free-vs-pro-plan.md that
  the free tier will never gain one.
